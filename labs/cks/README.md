# CKS lab

A kubeadm cluster on KVM VMs, for CKS practice. Terraform creates the VMs on kube-01 through the `dmacvicar/libvirt` provider (pinned to 0.8.3); cloud-init prepares the nodes.

## What it builds

| VM | IP | vCPU | RAM | Disk |
|----|----|------|-----|------|
| controlplane | 192.168.60.10 | 2 | 3 GB | 30 GB |
| worker1 | 192.168.60.11 | 2 | 2 GB | 30 GB |
| worker2 | 192.168.60.12 | 2 | 2 GB | 30 GB |

- Ubuntu 24.04, containerd (systemd cgroup driver), kubelet/kubeadm/kubectl from `pkgs.k8s.io`, held at `k8s_minor` (default `v1.35`)
- NAT network `cks`, `192.168.60.0/24`, domain `cks.lab`: the VMs reach the internet, the home LAN cannot reach them
- Pod CIDR `10.244.0.0/16`, Cilium as CNI
- User `student`: SSH with key only, passwordless sudo, `alias k=kubectl` with completion

## Bootstrap modes

| `auto_bootstrap` | Result |
|------------------|--------|
| `true` (default) | `kubeadm init` + Cilium on the control plane, workers join on their own. Ready about 5 minutes after `apply`. |
| `false` | Nodes prepared, no cluster. You run `kubeadm init/join` yourself. |

## Requirements on the host

- KVM/QEMU and libvirt, user in the `libvirt` and `kvm` groups
- `genisoimage` (the provider uses it to build the cloud-init ISO)
- Terraform >= 1.5
- libvirt storage pool `default`
- `~/.ssh/id_ed25519.pub`
- [noble-server-cloudimg-amd64.img](https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img) in `~/images`

## Usage

```bash
terraform init
terraform apply                              # or: terraform apply -var auto_bootstrap=false
terraform output -raw connect                # how to reach the nodes
terraform destroy                            # free the RAM when done
```

From kube-01:

```bash
ssh student@192.168.60.10
cloud-init status --wait     # wait for the bootstrap
k get nodes -o wide
cilium status
```

If the network is down, use the serial console: `virsh -c qemu:///system console cks-controlplane` (user `student`, password from `lab_password`, default `student`; exit with `Ctrl+]`).

## Variables

| Name | Default | |
|------|---------|---|
| `k8s_minor` | `v1.35` | Keep it aligned with the current CKS exam |
| `auto_bootstrap` | `true` | See above |
| `lab_password` | `student` | Console only, SSH stays key-only |
| `nodes` | 3 VMs above | Add or resize nodes here |

## Notes

- The kubeadm token is generated by Terraform and stored in `terraform.tfstate`, which is not committed.
- Workers join with `--discovery-token-unsafe-skip-ca-verification`. Fine for a lab; for practice, use `--discovery-token-ca-cert-hash`.
- Recreating the VMs changes their SSH host keys: `ssh-keygen -R <ip>`.
